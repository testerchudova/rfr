# Тестовые данные Rangiffler

1. Каждый тест получает уникальные данные через `TestUser.unique()`; пользователей других тестов не использует.
2. Владелец данных — дерево `UserFixture`; в JUnit Store регистрируется его корень до `create()`.
3. Новое предусловие добавляется отдельным декоратором и композицией в `UserRequest.fixture()`.
4. Декоратор записывает дочернюю фикстуру в свой список до её `create()` и закрывает детей, затем `origin` через `TearDown`.
5. SQL находится только в объектах строк `data/db`; тесты и расширения вызывают их методы.
6. Создание auth-аккаунта не создаёт API-профиль: `SingleUserFixture` создаёт оба явно.
7. Очистка адресная, работает после частичной подготовки и падения теста; широких `DELETE`/`TRUNCATE` нет.
8. Пул заранее заведённых пользователей применяй только там, где создание невозможно; аренду возвращай в очередь, записи БД не удаляй.
9. Жизненный цикл проверяй мишенями EngineTestKit: данные существуют во время теста и освобождены после успеха и ошибки.
