## По чтению кода

В окончательной версии незакрытых замечаний не обнаружено.

| Ресурс | Получение и владелец | Хранение и освобождение |
|---|---|---|
| Основной пользователь | SingleUserFixture внутри дерева декораторов | Корень помещается в Store до create; закрывается профиль, затем auth-аккаунт |
| Приглашённые | UserWithOutcomeInvitationsFixture создаёт через SingleUserFixture | В invitees до создания; TearDown закрывает детей, затем origin |
| Связи дружбы | Дерево фикстур; requester исходящего приглашения — основной пользователь | Адресно удаляются при удалении API-профиля |
| Арендованный пользователь | StaticUserFixture, ограниченный BlockingQueue.poll | В leased; Store вызывает идемпотентный close, возвращающий только свою аренду |
| Браузерные ресурсы | @UsePlaywright | Новые тесты и расширения самостоятельно их не закрывают |

Принятые замечания закрыты:

1. **Ложно зелёная очистка при пустых reporting entries.** Helper UserExtensionTest теперь проверяет ожидаемый исход мишени, намеренное исключение и обязательные непустые имена до SQL. Успешная OutcomeInvitation использует тот же helper. Закрытие подтверждено мутацией без Store.put и успешным восстановленным прогоном.
2. **Недостаточное покрытие аварийных путей.** Добавлены failedOutcomeInvitationIsRemoved, partialOutcomePreparationIsRemoved и возврат трёх аренд при таймауте четвёртого параметра. Все прошли запуск ревьюера.

Правила 9 и 10 rfr-test-review соответствуют проверенным ситуациям. README уточняет необходимость MySQL для DB-проб.
