# Ревью ДЗ №04

Ревью выполнено отдельным `test-reviewer` по `.claude/skills/rfr-test-review/SKILL.md`. Агент читал изменения и затронутые файлы; код не менял. Результат его независимого запуска приведён ниже.

## Принятые замечания

1. **HTTP-критерии отличались от `wait-for-stand.sh`.** Скрипт API без `curl -f` принимает любой завершённый HTTP-ответ; auth/front — 2xx/3xx. Скрипт не следует редиректам, Java-клиент первоначально следовал. Исправлены статусный критерий и политика редиректов. Проба API401 на прежнем условии упала; затем API401 и auth302 прошли. Это проверка эквивалентности критерия, а не утверждение, что текущая корректная операция `{__typename}` должна возвращать401: повторная проверка корректного JSON дала200.
2. **Разные папки Allure при прямом JUnit-запуске.** В `TestConfig` использовался свой default, а Allure writer выбирал другой. Добавлен общий `allure.properties`, путь читается тем же `PropertiesUtils`, что использует Allure. Проба без системного override создаёт настоящий `AllureLifecycle`, пишет JSON с собственным UUID, проверяет его в каталоге окружения и переносит только свой артефакт во временную папку. Проверка прошла.
3. **Итоговый успех не доказывал отсутствие Upgrade.** Проверка HTTP/1.1 дополнена счётчиком Upgrade-запросов с ожидаемым значением0. Это исключает ложно зелёный результат, если первая попытка использовала HTTP2, а повторная — HTTP1.

Дополнительная проверка основного агента обнаружила, что плагин Allure Gradle4.3.0 добавляет собственный JVM-аргумент каталога после `systemProperty`. Настройка перенесена в `adapter.resultsDir`, дублирующее свойство убрано. Фактический JVM-аргумент проверен, затем окружение найдено в новом явно заданном каталоге при ошибке Flyway. Проба ошибки `StandSchemaExtension` добавлена в EngineTestKit.

## Проверка правила13 на намеренной ошибке

Временная правка подключала `StandReadinessExtension` через `@ExtendWith` над `MainPageTest` и удаляла его из SPI. Ревьюер выдал P1: `FriendsTabTest` остаётся без `beforeSuite`; отдельный запуск этого класса перейдёт к Playwright при недоступном фронте. Причина указана по правилу13: production-реализации `SuiteExtension` должны регистрироваться глобально через ServiceLoader, локальная аннотация делает подготовку зависимой от набора классов.

Ошибочная регистрация восстановлена. Проверка восстановления запускает отдельно FriendsTabTest с выключенным фронтендом и ожидает ошибку readiness до тел UI-тестов. Внутренние подставные реализации `SuiteExtension` в `@ProbeTarget` сохраняют разрешённое исключение.

## Владение ресурсами

| Ресурс | Владелец и освобождение |
|---|---|
| `SuiteRun` | Корневой Store, отдельный ключ на реализацию; закрытие вызывает afterSuite |
| HTTP-клиент и executor | Один вызов readiness; shutdownNow в finally |
| Сокет и попытки подключения | Сокет в try-with-resources; futures ограничены оставшимся бюджетом и отменяются |
| Подставные HTTP-серверы и свойства | ProbeStand; close останавливает серверы/executors и восстанавливает свойства; @Isolated исключает параллельное вмешательство других тестов |
| Environment и артефакт проверки writer | Закрываемые потоки; уникальный UUID у временного JSON, адресный перенос своего файла |

По повторному чтению исправлений новых production-дефектов не найдено. `supports` пропускает non-UI до регистрации в Store. В полном `:test` остаются унаследованные DB-пробы, которым нужна MySQL; отсутствие обращения к стенду у глобальных расширений не означает, что весь набор обходится без БД.
