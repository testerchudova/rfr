# rfr-e2e

Настройки и границы пакетов — в [README.md](README.md); новые классы размещай в существующих пакетах. Конфигурация читается только через `TestConfig`.

- До изменения Page Objects и компонентов прочитай [rfr-page-objects](../.claude/skills/rfr-page-objects/SKILL.md). Канонический skill один; копии не создавай.
- Вход выполняется через UI; токены в localStorage не подставляются.
- Тестовые пользователи принадлежат фикстурам `@User` → `UserExtension` → `UserFixture`; очистка адресная, без широких DELETE/TRUNCATE.
- MCP подтверждает локаторы и доступные имена. Корректность сценария подтверждает фактический JUnit-прогон `./gradlew e2e` с работающим стендом.
- Браузерные тесты помечай `@Tag("ui")`; `:rfr-e2e:test` исключает их, `:rfr-e2e:e2e` запускает только их.
- В Java, Gradle, SQL и properties модуля не добавляй комментарии и Javadoc: используй понятные имена и `@Step`.
